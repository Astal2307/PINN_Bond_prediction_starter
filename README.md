# Справедливая цена неликвидной облигации с колл-опционом

## Задача

Есть корпоративная облигация с фиксированным купоном. Торгуют ей редко: сделки проходят раз в несколько дней, мелкими лотами, и цены отдельных сделок могут заметно отличаться от справедливой. У эмитента есть колл-опцион: в указанную дату он вправе погасить выпуск досрочно по номиналу.

Нужно для каждого торгового дня окна оценки получить:
- **справедливую чистую цену** облигации, % от номинала;
- **Z-спред** этой цены к кривой ОФЗ, б.п.

Цена обязана считаться с помощью **PINN**: нейросети, которая решает уравнение для цены облигации в выбранной вами модели ставок и кредитного спреда. Модель, уравнение и способ калибровки вы выбираете сами.

## 1. Данные

### 1.1 Рынки

Данные разбиты на **рынки**. Рынок это папка `data/markets/<market>/` со случайным кодом (например, `5pga6wmq/`). В ней лежат ставки, кривая ОФЗ, целевая облигация и несколько других облигаций того же эмитента за весь период данных. Рынки не связаны между собой, модель калибруется на каждом рынке отдельно.

| Набор | Число рынков | Для чего |
|---|---|---|
| Public-рынки | 5 | Отладка: метрики и графики видны сразу после загрузки |
| Private-рынки | 20 | Итоговая оценка: метрики видны после окончания |
| Реальная облигация | 1 (АльфаБО-21, RU000A0ZYBM4) | Итоговый график, без метрики |

Какие рынки public, а какие private, указано в колонке `split` шаблона. Реальная облигация лежит в `data/real/` в том же формате; история сделок по ней прорежена до уровня неликвидной бумаги.

### 1.2 Состав папки рынка

```
<market>/
├── task.json                  целевая облигация и окно оценки
├── securities/<SECID>.json    описание выпуска
├── bondization/<SECID>.json   купоны, колл, погашение
├── history/<SECID>.json       дневная история торгов
├── zcyc.json                  G-кривая ОФЗ
└── ruonia.csv                 ставка RUONIA
```

Форматы совпадают с выгрузками Московской биржи (ISS) и сайта ЦБ.

**`task.json`**
```json
{
 "target": "ZZ0009B6MI57",
 "eval_from": "2025-04-08",
 "eval_till": "2026-10-07"
}
```
`target` задаёт целевую облигацию, `eval_from` и `eval_till` задают окно оценки. История в папке начинается раньше окна, её можно использовать для калибровки.

**`securities/<SECID>.json`**: блок `description` с полями `name, title, value, type, …` (код, наименование, номинал, дата погашения, тип купона).

**`bondization/<SECID>.json`**:

| Блок | Ключевые поля | Описание |
|---|---|---|
| `coupons` | `coupondate`, `startdate`, `value` (руб.), `valueprc` (% год.) | График купонов |
| `offers` | `offerdate`, `price` (% номинала), `offertype` | Колл-опцион: `offertype = "Колл-опцион"` |
| `amortizations` | `amortdate`, `value` | Погашение номинала |

**`history/<SECID>.json`**: блок `history`, по строке на каждый торговый день. Основные поля:

| Поле | Описание |
|---|---|
| `TRADEDATE` | Дата торгов |
| `NUMTRADES` | Число сделок за день, 0 если сделок не было |
| `VOLUME` | Объём, шт. |
| `VALUE` | Объём, руб. |
| `OPEN`, `HIGH`, `LOW`, `CLOSE` | Цены, % номинала, чистые |
| `WAPRICE` | Средневзвешенная цена, % номинала, чистая |
| `ACCINT` | НКД на дату торгов, руб. |
| `YIELDCLOSE`, `YIELDATWAP`, `DURATION`, `CALLOPTIONDATE` | Доходность, дюрация, дата колла |

Поштучных сделок нет, только дневные итоги. Часть полей может быть пустой.

**`zcyc.json`**:

| Блок | Поля | Описание |
|---|---|---|
| `params` | `tradedate, tradetime, B1, B2, B3, T1, G1…G9` | Параметры G-кривой ЦБ на каждый день |
| `yearyields` | `tradedate, tradetime, period, value` | Доходности на стандартных сроках, % год. |

**`ruonia.csv`**: таблица ЦБ, разделитель `;`, десятичная запятая.
```
Дата ставки;Ставка RUONIA, % годовых;Объем сделок RUONIA, млрд руб.;…
08.10.2026;9,96;475,23;…
```

Номинал облигаций 1000 руб., цены в % от номинала.

## 2. Что нужно сделать

1. **Подготовить данные**: ставки, кривую, параметры облигаций и историю торгов в удобном виде.
2. **Выбрать модель и вывести уравнение.** Выбрать факторы (например, короткую ставку и кредитный спред) и их динамику под риск-нейтральной мерой. Вывести уравнение в частных производных для цены целевой облигации и условия к нему: в дату погашения, на купонных датах, в дату колла, на границах области.
3. **Откалибровать модель** по данным рынка.
4. **Обучить PINN**, которая решает это уравнение. Вход сети: время и переменные состояния модели. Выход: чистая цена.
5. **Восстановить состояние на каждый день окна** (например, спред) по истории торгов, в том числе в дни без сделок, и получить из сети справедливую цену.
6. **Посчитать Z-спред** по своей цене (раздел 3.2).
7. **Реальная облигация.** Применить свой pipeline к реальной облигации и построить итоговый график (раздел 3.5).

### Бейзлайн

Даётся код бейзлайна, который проходит все шаги от папки рынка до `predictions.csv` и графика:
- модель: Васичек, откалиброванный по истории RUONIA, и постоянный спред;
- цена дня: `WAPRICE`;
- PINN: одна полносвязная сеть;
- состояние по дням: подбор спреда в дни со сделками и линейная интерполяция между ними.

Бейзлайн обучает сети по рынкам параллельно на всех ядрах CPU или на GPU, если он есть. Бейзлайн можно менять в любой части или заменить целиком.

## 3. Что сдать

Решение загружается на платформу ⟨ссылка⟩ одним zip-архивом:

```
submission.zip
├── predictions.csv
├── code.txt
└── pinn/
    └── <market>/
        ├── model.onnx
        └── manifest.json
```

Папка `pinn/<market>/` нужна для каждого рынка (public и private). `code.txt` содержит ссылку на репозиторий с кодом и хеш коммита (раздел 3.4).

### 3.1 `predictions.csv`

По строке на каждую пару (рынок, дата) из шаблона `predictions_template.csv`.

| Поле | Тип | Описание |
|---|---|---|
| `market` | str | Код рынка |
| `date` | str `YYYY-MM-DD` | Торговый день окна |
| `clean_price` | float | Справедливая чистая цена, % номинала |
| `zspread_bp` | float | Z-спред, б.п.; обязателен в строках с `z_required = 1` |
| `split` | str | Из шаблона, не менять |
| `z_required` | int | Из шаблона, не менять |
| `<state_1>…` | float | Переменные состояния сети на этот день, названия как в `manifest.json` рынка |

### 3.2 Как считать Z-спред

z находится из уравнения

```
dirty = Σ_k CF_k · exp(−(G(τ_k) + z) · τ_k)
```

где:
- `dirty = clean_price + ACCINT / 10`: грязная цена, % номинала;
- `CF_k`: оставшиеся купоны до первой даты колла включительно и номинал (100) в дату колла, % номинала;
- `τ_k` = (дата потока − дата оценки) / 365;
- `G(τ)`: G-кривая этого дня по параметрам `zcyc.params`, непрерывное начисление.

Сданный `zspread_bp` должен совпадать с пересчитанным из вашей цены с точностью до 1 б.п.

### 3.3 Файлы PINN

Для каждого рынка два файла: `pinn/<market>/model.onnx` и `pinn/<market>/manifest.json`.

**`model.onnx`**: вход `x` float32 размера `[N, d]`, `2 ≤ d ≤ 6`, первая колонка время t; выход float32 `[N, 1]`, чистая цена в % номинала.

**`manifest.json`** описывает переменные сети и уравнение вида

```
V_t + Σ_i μ_i V_i + ½ Σ_ij a_ij V_ij − k·V + f = 0
```

```json
{
  "time_origin": "YYYY-MM-DD",
  "variables": [
    {"name": "t", "lo": 0.0, "hi": 1.5},
    {"name": "r", "lo": 0.00, "hi": 0.40, "meaning": "short rate"},
    {"name": "s", "lo": -0.05, "hi": 0.15, "meaning": "credit spread"}
  ],
  "pde": {
    "drift":     {"r": "<выражение>", "s": "<выражение>"},
    "diffusion": {"r,r": "<выражение>", "s,s": "<выражение>", "r,s": "<выражение>"},
    "discount":  "<выражение>",
    "source":    "<выражение>"
  },
  "tables": {"theta": {"x": [ ... ], "y": [ ... ]}}
}
```

- `t = (дата − time_origin) / 365`; `lo` и `hi` задают область, на которой обучена сеть.
- `drift` задаёт μ_i, `diffusion` задаёт a_ij, `discount` задаёт k, `source` задаёт f.
- В выражениях можно использовать числа, имена объявленных переменных, `+ − * / **`, функции `exp, log, sqrt, abs, min, max`, таблицы из `tables` (линейная интерполяция по t) и две готовые функции целевой облигации: `coupon_rate(t)`, скорость начисления купона, и `accrued(t)`, НКД, обе в % номинала.
- Число и названия переменных выбираете вы.

### 3.4 Код

Репозиторий с кодом, открытый или с доступом для жюри. Одна команда собирает `submission.zip` из папок рынков. Зафиксированы seed и зависимости, есть README.

`code.txt` в загрузке, две строки:
```
https://github.com/<team>/<repo>
<хеш коммита, 40 символов>
```
По коммиту из последней успешной загрузки жюри проверяет воспроизводимость (раздел 4.2).

### 3.5 Итоговый график

По реальной облигации:
- точки: дни со сделками, размер точки по объёму;
- линия: справедливая цена по дням;
- вертикальная линия: дата колла;
- нижняя панель: Z-спред и, при желании, кредитный спред вашей модели.

График сохраняется в репозиторий как `real_bond.png`.

## 4. Проверка и оценка

### 4.1 Проверка формата

Решение не принимается, если:
- в архиве нет `predictions.csv`, `code.txt` или папки `pinn/<market>/` для какого-то рынка;
- нет обязательной колонки, есть дубликаты, пропущенные или лишние пары (рынок, дата);
- в обязательных полях есть нечисловые или бесконечные значения;
- `clean_price` вне [30; 200] или `|zspread_bp| > 5000`;
- `zspread_bp` отличается от пересчитанного из цены больше чем на 1 б.п. более чем в 1% строк.

### 4.2 Проверка PINN

Пункты 1–3 платформа проверяет автоматически на каждом рынке при каждой загрузке и показывает результат отдельно от метрик точности. Загрузка, не прошедшая пункты 1–3, не участвует в оценке точности.

1. **Невязка уравнения.** В случайных точках области из `manifest.json` производные сети считаются конечными разностями, относительная невязка `rms(R) / rms(|V_t| + |k·V| + |f|)` должна быть ниже 0,05.
2. **Корректность уравнения.** Дисконт зависит от переменных ставки и спреда, диффузия ненулевая и неотрицательно определённая, переменные состояния из `predictions.csv` лежат внутри области.
3. **Согласованность.** Сеть в ваших переменных состояния даёт ваши цены из `predictions.csv` с точностью 0,05 п.п.
4. **Воспроизводимость.** После окончания жюри случайно выбирает 3 private-рынка, переобучает на них сеть вашим кодом с другим seed и сравнивает с загруженными сетями и ценами.

### 4.3 Метрики

- **Основная:** RMSE чистой цены по всем дням окна, по каждому рынку, затем среднее по рынкам.
- **Дополнительная:** RMSE Z-спреда по строкам с `z_required = 1`, среднее по рынкам.

Предсказания сдаются сразу по всем рынкам. Метрики по public-рынкам видны сразу после загрузки, по private-рынкам открываются после окончания; итог считается по private-рынкам.

К каждой загрузке платформа строит страницу с графиками: по public-рынкам полные (ваша цена, сделки, справедливая цена), по private-рынкам сводные (ошибка в зависимости от срока до колла, в дни со сделками и без них). Полные графики по private-рынкам открываются после окончания.

## 5. Правила

1. Цены в `predictions.csv` получены из PINN, которая решает уравнение из `manifest.json`. Другие численные методы можно использовать для проверки и сравнения.
2. Для public- и private-рынков используются только файлы из папки рынка. Для реальной облигации можно брать любые открытые данные, укажите их в README.
3. Загрузок на платформу: не больше 100 на команду. В итог идёт последняя успешная загрузка.
4. Размер одного ONNX до 50 МБ, расчёт 10⁵ точек не дольше 10 с.
