# Бейзлайн

Проходит все шаги постановки от папок рынков до готовой загрузки:

| Шаг постановки | Модуль | Что делает бейзлайн |
|---|---|---|
| 1. Данные | `data.py` | читает файлы ISS и RUONIA рынка, купонный график и колл целевой бумаги |
| 2. Модель и уравнение | `model.py` | Васичек для ставки, постоянный спред; уравнение для чистой цены |
| 3. Калибровка | `calibrate.py` | Васичек по недельной RUONIA (AR(1)); уровень спреда и область сети по сделкам (`WAPRICE`) |
| 4. PINN | `pinn.py` | одна сеть 4×64 tanh, невязка + погашение + мягкое условие колла; Adam, затем L-BFGS |
| 5. Состояние по дням | `inverse.py` | спред подбирается по `WAPRICE` в дни со сделками, между ними — линейная интерполяция |
| 6. Z-спред | `zspread.py` | Z-спред по конвенции раздела 3.2 |
| экспорт | `export.py` | `pinn/<market>/model.onnx` и `manifest.json` |
| сборка | `submission.py` | `predictions.csv`, `code.txt`, `submission.zip` |
| 7. Реальная облигация | `plot.py` | `real_bond.png` |

Каждый модуль можно заменить отдельно; связывает их `run.py` (функция `market_job`).

## Установка и запуск

Нужен Python 3.9–3.12.

```bash
python -m venv .venv
```

```bash
source .venv/bin/activate
```

```bash
pip install -r baseline/requirements.txt
```

```bash
python -m baseline.run --data data/ --out out/
```

Результат в `out/`:
- `submission.zip` — готовая загрузка (`predictions.csv`, `code.txt`, `pinn/<market>/`);
- `real_bond.png` — итоговый график по реальной облигации (скопируйте его в корень своего репозитория);
- `real_prices.csv`, `markets_info.csv` — цены по реальной облигации и параметры калибровки по рынкам.

Перед загрузкой проверьте архив: `python -m checker out/submission.zip --data data/` (см. `checker/README.md`).

### `code.txt`

Ссылка и хеш коммита берутся из git-репозитория, из которого запускается бейзлайн (`git remote get-url origin`,
`git rev-parse HEAD`). Ссылка должна быть https-адресом вашего репозитория с кодом. Если вы склонировали репозиторий
организаторов, сначала перенесите код в свой репозиторий и закоммитьте изменения:

```bash
git remote set-url origin https://github.com/<team>/<repo>.git
```

```bash
git push origin HEAD
```

Ссылку можно указать и явно: `python -m baseline.run --repo-url https://github.com/<team>/<repo>`.
Без git-репозитория бейзлайн всё посчитает, но `submission.zip` не соберёт и объяснит, что сделать.

## Параллельность и время

- CPU: рынки обучаются параллельно, по процессу на ядро, один поток torch на процесс (`--jobs N` — число процессов).
- GPU: `--device cuda` (NVIDIA) или `--device mps` (Apple), по умолчанию 4 процесса на устройстве.
  `--device auto` (по умолчанию): CUDA, если она есть, иначе CPU. Apple MPS на маленькой сети бейзлайна медленнее CPU
  (см. таблицу), поэтому включается только флагом. Результаты на CPU не зависят от числа процессов;
  на GPU цены отличаются от CPU в пределах ~0,1 п.п. (другая арифметика), точность та же.
- Если невязка сети на рынке выше 0,035 (порог платформы 0,05), сеть переобучается с другим seed, до 3 попыток.
- Seed фиксирован для каждого рынка (`--seed` сдвигает все seed).

Время полного прогона (25 рынков + реальная облигация, 3000 итераций Adam + 100 L-BFGS):

| машина | устройство | процессов | время |
|---|---|---|---|
| Apple M5 (4 производительных + 6 энергоэффективных ядер), Python 3.9 | CPU | 4 | 3 мин 40 с |
| | CPU | 6 | 4 мин 00 с |
| | CPU | 8 | 3 мин 28 с |
| | CPU | 10 (по умолчанию) | 3 мин 56 с |
| | Apple MPS | 4 | 4 мин 27 с |

На 8-ядерном ноутбуке без GPU, вдвое медленнее M5, ожидается 7–8 минут. Если дольше 15 минут, уменьшите
`--adam-iters` (2000 сокращает время на треть). Самый долгий рынок обычно тот, где понадобилось переобучение
(до 3 попыток подряд).

Для отладки: `--markets код1,код2` (только эти рынки, zip не собирается), `--no-real`,
`--adam-iters`, `--lbfgs-iters`.

## Что можно улучшить

Бейзлайн намеренно простой. Его RMSE чистой цены на public-рынках — около 1,8 п.п.
Основные слабые места:
- шум сделок не фильтруется: спред дня берётся прямо из `WAPRICE`;
- спред в уравнении постоянный, хотя в данных он меняется;
- Васичек по RUONIA не использует G-кривую;
- другие облигации эмитента не используются;
- у сети нет признаков фазы купона, а колл задан мягким штрафом.
