# Локальная проверка загрузки

```bash
python -m checker out/submission.zip --data data/
```

Скрипт делает ровно те же проверки, что платформа: код проверок (`checker/core.py`) и пороги (`checker/limits.json`)
у платформы те же самые. Отличие одно: истины у checker нет, поэтому метрик точности он не считает.
Код возврата 0 — загрузка будет принята; 1 — будет отклонена. С флагом `--details` печатается таблица PINN по всем рынкам.

## Что проверяется

**Архив.** Нужны `predictions.csv`, `code.txt` и папка `pinn/<market>/` для каждого рынка из шаблона.
Допускается одна вложенная корневая папка; `__MACOSX/`, `.DS_Store` и прочие лишние файлы игнорируются.
Отклоняются: не zip, битый архив, пути с `..` или абсолютные пути, слишком большой распакованный объём
(больше 1500 МБ) или подозрительная степень сжатия.

**`code.txt`.** Первая строка — https-ссылка на репозиторий, вторая — хеш коммита из 40 шестнадцатеричных символов.

**`predictions.csv`.**
- Кодировка UTF-8, разделитель — запятая, десятичный знак — точка. BOM и переводы строк CRLF допускаются.
  Файл с разделителем `;` или десятичной запятой отклоняется с подсказкой.
- Обязательные колонки: `market`, `date`, `clean_price`, `zspread_bp`. Колонки `split` и `z_required` можно не включать,
  но если они есть, то должны совпадать с шаблоном. Колонки состояний называются как переменные в `manifest.json`
  рынка. Остальные колонки игнорируются.
- Каждая пара (рынок, дата) шаблона — ровно один раз, без лишних пар.
- `clean_price` — конечное число в [30; 200] во всех строках.
- `zspread_bp` — конечное число, `|zspread_bp| ≤ 5000`, в строках с `z_required = 1`. В строках с `z_required = 0`
  поле может быть пустым.
- Z-спред пересчитывается из вашей цены по конвенции раздела 3.2. Расхождение больше 1 б.п. допускается не более чем
  в 1% строк с `z_required = 1`.

**PINN, по каждому рынку.**
- `model.onnx`: не больше 50 МБ; ровно один вход `x` типа float32 формы `[N, d]`, `d` = число переменных
  в `manifest.json` (2–6); выход float32 формы `[N, 1]`; 10⁵ точек считаются не дольше 10 с (1 поток CPU);
  в точках области нет NaN и inf.
- `manifest.json`: обязательные ключи `time_origin` (YYYY-MM-DD), `variables` (первая — `t`, у каждой `name`, `lo`, `hi`),
  `pde.diffusion`, `pde.discount`. Ключи `pde.drift`, `pde.source` и `tables` необязательны (по умолчанию 0).
  Выражения разбираются безопасным парсером: числа, имена переменных, `+ - * / **`, функции `exp log sqrt abs min max`,
  таблицы из `tables`, `coupon_rate(t)`, `accrued(t)`. Длина выражения — не больше 2000 символов.
- Невязка: 4000 случайных точек во внутренней части области (10–90% по каждой переменной), не ближе 4 дней
  к купонным датам и дате колла. Производные считаются центральными разностями: шаг по t — 2 дня,
  по остальным переменным — 0,5% ширины области. Относительная невязка `rms(R) / rms(|V_t| + |k·V| + |f|)`
  должна быть ниже 0,05. Точки выбираются с фиксированным seed, одинаковым у checker и платформы.
- Корректность уравнения: дисконт зависит хотя бы от одной переменной состояния и не постоянен;
  диффузия ненулевая и неотрицательно определена во всех точках.
- Переменные состояния из `predictions.csv` и время дат окна лежат внутри области `[lo; hi]` из `manifest.json`.
- Согласованность: сеть в ваших состояниях даёт ваши цены с точностью 0,05 п.п. (максимум по строкам рынка).

`coupon_rate(t)` и `accrued(t)` строятся по купонам целевой облигации из `bondization`, в % номинала,
на оси `t = (дата − time_origin) / 365`. НКД в них линейный внутри купонного периода.
